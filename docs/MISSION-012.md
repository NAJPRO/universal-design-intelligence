# Mission 012 — Independent Agent Validation

Experiment started 2026-10-30 UTC, continuing 2026-10-31 local time. This report separates an invalid pilot from the corrected primary experiment. No generated interface is controller-authored or repaired after agent submission.

## Frozen experiment

[Protocol and reproduction](../benchmarks/mission012/README.md), [task](../benchmarks/mission012/protocol/task.md), [rubric](../benchmarks/mission012/protocol/rubric.json), [settings](../benchmarks/mission012/protocol/settings.json) and [input hashes](../benchmarks/mission012/evidence/frozen.json) retain the experiment inputs. Tern Works is original MIT-compatible fictional inventory data, unrelated to user projects and previous reference implementations. Eighteen records include long names, restricted permissions, three categories, lifecycle states, zero/low stock, suppliers and lead times. The starting application contains only a skeleton. HTML/CSS/JavaScript, tokens and data are fixed; no framework or dependency choice varies across conditions.

The task requires consultation/comparison, search and combined filters, record actions, validated editing, recovery, accessible scrolling and keyboard/focus continuity. It prescribes neutral automation hooks and query-state entry points, but no cards, table conversion, track concealment or particular visual design. The full rubric is withheld from implementing agents.

A receives no design skill/runtime; B receives the frozen enhanced Mission 010 skill and pre-Mission-011 bundled runtime; C receives the current canonical skill/runtime. B/C project instructions advertise matching skill metadata and entry points, allowing the agent to select it. This tests project-catalog-assisted discovery; it does not establish implicit discovery for all installed Codex skill paths or other hosts. The launcher logs arguments, exit status and returned guidance. Full contracts are not preloaded.

Each is a fresh `codex exec` process using **gpt-6.1-sol, medium reasoning**, existing Codex CLI 0.164.0, identical tools and a **hard 900-second wall ceiling**, with a 720-second soft target. Actual tokens/time are recorded; no equal-token cap, sampling seed or backend-load control is claimed. The implementation prompt/context is fresh, without controller conversation, reference implementations, previous agent outputs or evaluation results.

Bubblewrap exposes only each condition's `/work`, required system binaries, read-only original inputs and that condition's skill/runtime. Separate HOME/CODEX_HOME, PID and IPC namespaces hide sibling runs, repository history and previous evidence. User configuration/rules, web search and delegation are disabled. No Git directory is mounted. Model API networking remains available in the shared host network namespace. Filesystem isolation is enforced, but loopback HTTP from another concurrent browser server is not blocked by a network boundary. No cross-run access is observed in retained command logs; strict isolation against that indirect channel is not established. This limits the strength of the contamination control and must not be described as complete cross-run read prevention. Authentication is mounted read-only and never copied into artifacts. Probe results and exact invocation arguments are retained per arm.

## Invalid pilot and preflight corrections

[The complete pilot](../benchmarks/mission012-pilot/evidence/INVALID-EXPERIMENT.md) is retained rather than silently discarded. The controller initially placed bundled runtimes one directory too high, breaking package-version lookup before any B/C retrieval. The supplied browser helper also had a double-slash routing error, and the isolated environment lacked an alternatives symlink needed by Chrome. Agents attempted recovery themselves; C exhausted its ceiling without a final report. **This pilot cannot establish UDI effectiveness.** Its implementations/captures are excluded from the primary comparison.

The primary experiment corrects the runtime location, browser route and system symlink mount before freezing. All three conditions restart from clean inputs. Per-arm preflight now requires successful capture, plus runtime version startup for B/C, before agent time begins. Preflight logs are separate from actual agent invocations. No implementing agent receives pilot outputs or findings. A's primary launch required one retry after automatic approval review timed out before process creation; this is an infrastructure event, not an implementation failure.

## Evaluation method

Submissions are copied unchanged to `sources/A|B|C`, hashed and diffed against starting files. Raw events retain successful/failed shell commands, tool output, verification attempts and final responses; per-arm UDI logs retain exact retrieval requests/results. Actual application of knowledge requires corroborating retrieved content, reported decisions and code behavior; invocation alone is insufficient.

Controller browser settings are Chrome 156.0.8078.47, DPR 1, 320/375/768/1440 CSS pixels at height 1000, populated/empty/loading/error/edit states, plus 375×320 editing. Measurements address page overflow, action travel, state recovery, invalid/valid save, permissions and focus continuity. Unsupported automation paths are distinguished from observed product defects. Short-height testing is not an actual OS keyboard test. Static visibility and screenshots do not establish screen-reader or touch conformance.

A separate label-blinded review is attempted using anonymous screenshots and a [fixed review prompt](../benchmarks/mission012/protocol/reviewer.md), withholding sources, condition mapping, retrieval and functional results. This is a separate model context, not an independent human/model panel. Controller source/interaction review remains unblinded. Visual judgments are reported separately from objective failures and warnings; no aggregate aesthetic/functional score is used.

A fresh reviewer context inspected18 anonymous images: four populated widths, error375 and editor375×320 per interface. The reviewer found **mixed advantages, no consistent visual winner**. A had the strongest overall density and320 adaptation, including readable full-width filters and a balanced metric rearrangement. Error recovery sits below the initial mobile viewport across samples; it remains operable through scrolling. Different short-editor scroll positions limit visual comparison. These are separate aesthetic/composition observations, not functional scores or proof of conformance.

## Verification and conclusion

The implementation experiment genuinely executed independent agents with isolated project files. **Retrieval is verified; selected application of current guidance is corroborated; overall responsive or visual superiority is not established.** C's tablet/comparison action access is a useful observed improvement in this sample, counterbalanced by narrower-width composition issues and failure to complete reporting inside the common budget. One generation per arm, backend variance and a single same-family reviewer prevent statistical or broad causal conclusions. The enhanced arm is deadline-censored, not a fully completed agent submission.

`pnpm install --offline --frozen-lockfile` succeeds; build, lint and type checks succeed. Standard concurrent `pnpm check` encounters two timing failures (existing CLI component5000ms and tarball15000ms tests), retained in the log. The same **181 tests across15 files pass sequentially** with `pnpm exec vitest run packages/cli/test packages/core/test packages/knowledge/test --no-file-parallelism`; no timeout/test/product code was changed to obtain this result. Do not describe the standard concurrent check as passing. Integrity verification passes443 checks, including frozen inputs, final submissions and all300 files plus file sets from Missions010/011. Package versions and lockfile are unchanged.

Remaining validation: per-run network isolation with restricted model-API egress, independent human/multiple-model review; repeated randomized runs with adequate hard token accounting and model/backend version pinning; physical touch, assistive technology/announcements, actual OS keyboards and cross-browser testing. Priority for a future experiment is reliable completion/report budgeting, readable320 control selections, compact metric composition and comparison/action access without sacrificing density. Do not expand domain packs based on this single result. No subsequent mission, publication or Git state operation was performed.
